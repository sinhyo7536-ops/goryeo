# 고려를 지켜라 — 2장·3장 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 2장 「양규와 흥화진」과 3장 「강감찬과 귀주 대첩」을 만들어 1차시(1~3장)를 처음부터 1차시 결과 카드까지 플레이할 수 있게 한다.

**Architecture:** 1장과 같은 장 모듈 인터페이스(`chapters/chN/{script,scene,chapter}.js`)를 쓴다. 장마다 다른 미니게임이 공통으로 쓰는 부품(방법 카드, 다시 하기·쉬운 모드, 화면 위 누르기 목표, 큰 행동 버튼, 타이머·카운터)과 날씨 입자(눈·비)를 `core/`에 새로 만든다.

**Tech Stack:** 기존과 같음 (Three.js r160, ES 모듈, 브라우저 테스트 하네스, `tools/test.ps1`).

**Spec:** `docs/superpowers/specs/2026-10-21-goryeo-game-design.md` (4장 2장·3장 절, 5장 미니게임 공통, 6장 연출)

## Global Constraints

- 이전 계획의 Global Constraints 전부(한국어 해설체, '서희 장군'·'사귀다' 금지, 해설·퀴즈는 출처 필수, 버튼 48px 이상, 터치만으로 완료 가능, 배경음 꺼짐).
- 미니게임 공통(spec 5장): 시작 전 방법 카드(키보드·터치 조작 함께 표시), 누르기·끌기만으로 가능, 실패하면 바로 다시, **같은 단계 3번 실패 시 쉬운 모드**.
- 별점: 2·3장은 담판 같은 '처음 고른 답'이 없으므로 `firstTryCorrect: 0, firstTryTotal: 0`, 쉬운 모드를 한 번이라도 쓰면 `easyModeUsed: true`.
- 분위기: 2장 `snow`(눈 내리는 겨울), 3장 `storm`(비바람). 입자 수는 `world.quality.particles` 배율.
- 대사·퀴즈 문장과 출처는 spec 4장 그대로. 숫자는 spec에 있는 것만(40만, 10만, 20만 8천, 1010, 1018년 12월, 1019년 2월).
- 장 하나는 약 10분: 탐험 2~3분, 미니게임 4~5분, 퀴즈 1~2분.

## Review Focus

1. **미니게임 실패를 반복하는 학생** → 3번째 실패 뒤 쉬운 모드로 바뀌어 반드시 끝낼 수 있고, 별점은 ★★☆ 이하가 된다. (Task 2 테스트 `minigame: third failure switches to easy mode`)
2. **화면 위 누르기 목표(사다리)를 빠르게 연타** → 한 번 누른 목표가 두 번 점수로 세지지 않는다. (Task 2 테스트 `taps: a target counts once`)
3. **타이밍 버튼을 너무 일찍 누름(둑 터뜨리기·공격 신호)** → 실패로 처리되고 힌트가 나온 뒤 다시 할 수 있다. 진도가 막히지 않는다. (Task 6 테스트 `ch3: early press fails with a hint and retries`)
4. **2장 도중 새로고침 후 이어하기(미니게임 단계)** → 장면이 미니게임 시작 상태로 맞춰지고 점수가 중복되지 않는다. (Task 4 테스트 `ch2: resume at minigame starts the wall defense`)
5. **1~3장을 모두 마침** → 1차시 결과 카드가 한 번 뜨고 세 장의 별점이 모두 보인다. (Task 7 테스트 `session1: card after chapter 3 lists all three chapters`)

### Task 1: 날씨와 분위기 (눈·비비람)

**Files:** Create `core/weather.js`, `tests/weather.test.js`; Modify `core/world.js`, `core/people.js`

**Interfaces:**
- Produces: `MOODS.snow` = 흐린 겨울(하늘 위 `0x8e9aa8`, 지평선 `0xd9dee3`, 안개 `[0xd5dbe0, 30, 120]`, 해 약하게 0.8, particles `'snow'`), `MOODS.storm` = 비바람(하늘 위 `0x3b4652`, 지평선 `0x76828c`, 안개 `[0x5f6b74, 20, 90]`, 해 0.5, particles `'rain'`).
- Produces: `createWeather(world, kind: 'snow'|'rain', { count = 600 })` → `{ points: THREE.Points, setWind(x: number) }` — `world.level`에 추가, 개수는 `count * world.quality.particles`, `world.onUpdate`로 카메라 주변 40×40 상자 안에서 떨어지고 다시 위로. 비는 빠르고(속도 18) 눈은 느림(1.5), `setWind`는 x 방향 흐름.
- Produces: `makePerson({ hat: 'general' })` — 붉은 술이 달린 투구 + 어깨 갑옷.

- [ ] Step 1: 테스트 `weather: snow count follows quality`(low 0.3 배율 → 180개), `weather: particles stay inside the box after many steps`, `world: snow and storm moods exist with fog`, `people: general hat builds`.
- [ ] Step 2: 실행 → FAIL. Step 3: 구현. Step 4: 실행 → PASS. Step 5: Commit `feat: 눈·비 날씨와 겨울·폭풍 분위기`.

### Task 2: 미니게임 공통 부품

**Files:** Create `core/minigame.js`, `tests/minigame.test.js`; Modify `core/main.js`, `styles.css`

**Interfaces:**
- Produces: `showHowTo(ui, { title, steps: string[], keyboard: string, touch: string }) → Promise<void>` ('시작' 버튼).
- Produces: `runWithRetries(ctx, attempt: (easy: boolean) => Promise<boolean>, { failHint }) → Promise<{ easyModeUsed: boolean }>` — 실패하면 `failHint`를 해설 아닌 '안내'로 보여 주고 다시, 3번째 실패 뒤부터 `easy=true`.
- Produces: `createTapTargets(ctx) → { add(obj3d, { label, onTap }): Target, remove(t), clear() }` — 3D 물체 위치를 화면에 투영한 64px 원형 버튼(`.tap-target`), 매 프레임 위치 갱신, 화면 밖이면 숨김. 한 번 눌린 목표는 즉시 비활성(중복 점수 방지).
- Produces: `actionButton(ctx, label) → { wait(): Promise<void>, remove() }` — 화면 아래 가운데 큰 버튼(`.big-action`), 클릭·E·스페이스로 누름.
- Produces: `hud.setTimer(seconds | null)`, `hud.setCounter(text | null)` (screens.js createHud에 추가).
- `ctx`에 `ui`(UI 루트)와 `testHooks`(테스트에서만 채우는 빈 객체)를 추가한다.

- [ ] Step 1: 테스트
  - `minigame: third failure switches to easy mode` — attempt가 [false,false,false,true] 순서로 결과를 내고, 넘어온 easy 인자가 [false,false,false,true], 반환 `{ easyModeUsed: true }`.
  - `minigame: success first time is not easy` → `{ easyModeUsed: false }`.
  - `taps: a target counts once` — 같은 목표 버튼을 두 번 클릭해도 onTap 1회.
  - `action: E key and click both press the big button`.
  - `howto: shows keyboard and touch lines and resolves on 시작`.
- [ ] Step 2: FAIL. Step 3: 구현. Step 4: PASS. Step 5: Commit `feat: 미니게임 공통 부품`.

### Task 4: 2장 「양규와 흥화진」

**Files:** Create `chapters/ch2/script.js`, `chapters/ch2/scene.js`, `chapters/ch2/chapter.js`, `tests/ch2.test.js`; Modify `chapters/index.js`, `core/precache.js`, `tools/script-table.html`

**Interfaces:**
- Consumes: Task 1~3 전부, 1장과 같은 장 모듈 인터페이스.
- 장면 `buildCh2Scene(world)`: 눈 덮인 흥화진 — 돌 성벽으로 둘러싼 네모난 성(안쪽 20×20), 성문, 성안 초가·창고, 성벽 위 계단, 북쪽 바깥에 거란 진영. 성 밖 남쪽 들판(백성 구출용, z 30~70). NPC: `soldier`, `yanggyu`(general), `villager`. 반환 `{ wallSpot: { cam, ladderSlots: [x,z][6] }, field: { bounds, captives: [x,z][6] } }`.
- 탐험: 병사(!) → 양규(!) → 성벽 계단(빛나는 원). 백성은 언제든 대화.
- 미니게임 1 「성벽 방어」: 고정 카메라로 성벽 바깥을 내려다봄. 사다리 6자리 중 무작위로 사다리가 걸리고(쉬운 모드는 간격 1.6배) 4초 안에 누르지 않으면 꼭대기에 닿는다. 45초 버티기, 꼭대기에 닿은 사다리 3개 이상이면 실패. 남은 시간은 `hud.setTimer`, 막은 수는 `hud.setCounter`. 끝나면 해설 `[S15]`.
- 미니게임 2 「백성 구출」: 들판으로 이동, 끌려가는 백성 무리 6개가 북쪽으로 천천히 이동(쉬운 모드 절반 속도). 가까이(2.0) 가면 구출. 90초 안에 4무리 이상 구출이면 성공. 목표 화살표는 가장 가까운 무리. 끝나면 해설 `[S15]`.
- 결과 대사·퀴즈는 spec 그대로.
- `enterStage(ctx, 'minigame')`: 성벽 방어부터, `'quiz'`: 들판 결과 상태.

- [ ] Step 1: 테스트 `ch2: script passes validation`, `ch2: scene builds with 3 npcs and 6 ladder slots`, `ch2: completes with touch-only actions`(봇), `ch2: resume at minigame starts the wall defense`(enterStage 후 카메라 고정 모드), `ch2: failing the wall three times turns on easy mode`(봇이 사다리를 안 누르도록 → 3회 실패 후 easy, 그다음 봇이 누름 → easyModeUsed true).
